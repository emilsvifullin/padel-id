# Padel ID 1.2.0 — приёмка кандидата

Обновлено 12.10.2026. Версия 1.2.0, build 3. Разработка выполнена локально;
production-релиз пока не опубликован. Пользователь явно поручил завершить
его сейчас и разрешил необходимые Git/migrations/API/deployment/release операции
после резервирования и CI. МегаФон без VPN исключён из текущей поставки и
отложен отдельно. Физическая приёмка не выполнена и не объявляется успешной.
Владелец явно согласовал уведомления внутри приложения для 1.2.0 и APNs позже.
Shipping push NO — согласованное ограничение; APNs не блокирует этот релиз.
Действующий secret сохраняется, Shift Register не меняется.
Действующий API сообщает revision `b93723db3c71e9a3f28187c38ffd5d84c4f63a74`.
Десять новых миграций 1.2.0 применены только к локальному disposable stack;
локальная полная цепочка содержит 24 миграции. Hosted база не изменена.
Read-only GitHub проверка подтверждает опубликованные v1.0.0 и v1.1.0;
1.2.0 — следующий номер, `release-history-current.json`.

## Реализовано и проверено локально

- Нативные пять вкладок, единая дизайн-система, автоматическая/светлая/тёмная
  темы; настоящие UIKit alternate icons: Лайм по умолчанию, Графит, Мяч.
- Личные/групповые чаты, игровые группы, подписки, публикации, комментарии,
  реакции, серверный inbox, блокировки, приватность, жалобы и модерация.
  Списки ленты/комментариев/событий, inbox и conversations обновляют каноническое
  посещённое окно до 150 строк, включая auto-refresh/polling;
  закрытое содержимое не сохраняется в дисковом кеше этих списков.
  Модератор получает только актуальный текст конкретного reported item, без всей
  чужой переписки и без сохранения удалённого текста. Определённый4xx позволяет
  исправить публикацию; новый key создаётся только при изменении payload,
  неопределённый повтор сохраняет прежний payload/key.
- Приватные аватары: protected API и authenticated Storage с live-session/
  visibility/owner guards, запрет signed links/copy/move/list. Старый image cache
  очищается; возврат через gateway корректно учитывает базовый путь. Реальный
  Auth/Storage E2E проверил блокировку и истёкшую сессию, не только API proxy.
- Закрытые игры, приглашения, очередь ожидания, недельные серии с timezone,
  прежний надёжный outbox результата и сохранённая рейтинговая математика.
- Тренировки подтверждённых тренеров, турниры Americano/Mexicano/King of the
  Court/Round Robin, регистрация, согласие пары, раунды, версии счёта и четыре
  подтверждения. Очки соревнований не меняют рейтинг обычных матчей.
  Профиль подтверждённого тренера показывает квалификацию/описание и ведёт в
  реальное расписание с записью; свои события доступны в истории, ближайшее
  принятое будущее событие — на Главной. Перенос/редактирование открытого события
  сохраняет записи участников, защищает metadata_version и уведомляет участников.
  После score 409 клиент загружает канонический счёт/версию до исправления.
- Каталог клубов/кортов: поиск, проверенные координаты/карта, фотографии,
  инфраструктура, описание, активности и администрирование с защитой версий.
  Переход к бронированию доступен только при проверенной внешней ссылке.
  Собственные реальные слоты/платежи без интеграции клуба не имитируются.
- Полный локальный путь APNs: iOS permission/token/registration/logout/tap,
  SQL очередь с проверками приватности, отдельный Node HTTP/2 provider/worker,
  build/provisioning gates. По умолчанию выключен: Apple provisioning/ключ и
  работающий worker не предоставлены; фактическая доставка не проверена.
- Выбор API-маршрута до записи, отказ от HTTP redirects, ограниченные deadlines,
  сохранённый ключ при ручном retry, диагностика primary/fallback. Production
  fallback остаётся пустым до сетевой и серверной приёмки.

## Сеть и действующий секрет

На iPhone 17 Pro Max / iOS 27.0.1 пользователя старый Vercel API и новый
`api-padel.shiftregister.ru` недоступны без VPN через Алмател и МегаФон.
`vercel.com` открывается. Это подтверждает отказ соединения с конкретными
API-путями; механизм DNS/IP/SNI-фильтрации достоверно не установлен.

По разрешению владельца опубликован Supabase `gateway`, сейчас ACTIVE version 4,
в режиме relay к фиксированному существующему Vercel API. Никакой gateway secret
не копируется и не заменяется. Shallow/deep health возвращают 200 с прежней
production revision; anonymous `/v1/me` возвращает 401. Пользователь подтвердил:
новый путь работает без VPN через Wi-Fi, но не через МегаФон. Официальный
альтернативный hostname `functions.supabase.co` через МегаФон тоже не открывается.
Поэтому сетевое исправление **не принято**, маршрут в production iOS не включён.

Согласованность существующего ключа проверена без раскрытия: запрос recovery для
несуществующего случайного адреса и неверного recovery key прошёл серверную
проверку общего секрета и получил ожидаемый 403 `invalid_recovery`. Аккаунт/пароль
не менялись. Один старый deep health с fail-open limiter не был бы достаточным
доказательством. Функция account при read-only проверке ACTIVE version 4; её не
развёртывали в рамках этой работы. Vercel config и hash базы не менялись.

Shift Register исследован только read-only. Его страница размещена на GitHub
Pages, API выбирается между Vercel proxy и Supabase. Последующая проверка
пользователя показала, что **оба этих API тоже не открываются через МегаФон**.
Доступная страница не доказывает свежий запрос к серверу; конкретный кеш/маршрут
браузера не установлен. Другой проект не изменён.

Подготовлен отдельный Node/Caddy relay без секретов, локальный Docker build и
запуск проверены. Он требует доступного серверного хостинга и собственной
физической приёмки. У владельца только домен; платный сервер он явно отклонил, VPS/ресурсы не покупались,
DNS дополнительно не менялся. Relay агрегирует upstream IP rate limits:
проверенный источник caller IP остаётся обязательным условием production-трафика.
См. `shift-register-network-comparison.md` и `server/deploy/README.md`.

По отдельному явному разрешению опубликован только изолированный Netlify
read-only health probe:
[проверка health/deep](https://padel-id-network-probe.netlify.app/v1/health?deep=1).
Пользователь зарегистрировался и разрешил CLI authorization; Free $0 подтверждён
в UI. Site `2df11cca-1f71-4826-9a84-5c5977cd086f`, deploy
`6acbf908b35357bcd95b784d`. Public доступ открыт только новому probe, previews
private. Production API/DNS/Supabase/Vercel/secrets не изменены. Bundle содержит
только health и два pure helpers; 4 local probe tests + 22 relay regressions и actual
offline Netlify bundling passed. Это сетевой probe, не новый API приложения.

Hosted проверка 6/6 passed: системный curl проверил strict TLS, без redirects/
cookies. GET shallow/deep health 200 возвращает configuration_required,
mode network_verification, upstream_status: ok и прежний commit b93723; deep
возвращает database: ok, shallow — not_checked. POST health, `/v1/me`, default
function URL и arbitrary query 404. Proof: `netlify-probe-hosted-verification.json`.
Пользователь подтвердил на физическом iPhone без VPN: **Алмател Wi-Fi работает,
МегаФон mobile data URL не загружает**. Следовательно, probe не решил мобильную
доступность и не принят как app fallback. Точный DNS/IP/TLS/network механизм не
установлен; это не доказательство недоступности всех сервисов Netlify. Яндекс и
apple.com через тот же МегаФон без Wi-Fi/VPN открываются: общий мобильный
интернет работает, но точная причина недоступности API не установлена.
