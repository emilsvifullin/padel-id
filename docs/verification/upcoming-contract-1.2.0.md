# Future game extension 1.2.0

Existing scored results, rating and future-match tables stay authoritative.

* `POST /v1/upcoming-matches` accepts existing fields plus optional `visibility:public/private` (default public). Existing response adds `visibility`, `series_id:null|uuid`, `occurrence:int|null`, viewer `can_waitlist` and `can_invite`; existing fields retained.
* `POST /v1/upcoming-matches/series` requires Idempotency-Key UUID. Body `{match:<scheduled input without client_id>,occurrences:2..12,interval_weeks:1..4}`. RPC `create_scheduled_series(p jsonb,p_client_id uuid)` returns `{series_id:uuid,items:[ScheduledMatch]}`. All dates bounded by existing 180-day window; transaction creates all or none; replay requires same semantic payload and returns original series. Original weekday/local clock preserved across timezone/DST only if supplied explicit `time_zone` (IANA timezone) in body. Default Europe/Moscow for target product; UI should pass user's timezone.
* `POST /v1/upcoming-matches/:id/invitations` body `{player_id:uuid}`. RPC `invite_scheduled_player(p_match uuid,p_player uuid)`; owner only, accepted friends only, no block, active future event. Invitation does not reserve a seat; status `invited`.
* `POST /v1/upcoming-matches/:id/invitations/respond` body `{decision:accepted/declined}`. RPC `respond_scheduled_invitation(p_match uuid,p_decision text)`; own invitation only. Accepted consumes capacity atomically, preserves established level guard. Full event -> scheduled_match_full; invitation stays pending. Decline status rejected. Repeats same decision idempotent.
* `POST /v1/upcoming-matches/:id/waitlist` no body. RPC `waitlist_scheduled_match(p_match uuid)`. Explicit consent to wait, status `waitlisted`; no seat and no sports rating change. Idempotent repeated wait. Allowed only full game (otherwise invalid_request; regular join applies). When a seat opens queue participants get generic inbox notification and must join/apply themselves; invitation status tracked via invited_at so owner-approved invite can be accepted after wait.
* Existing join works for public game or own invited/accepted/pending/waitlisted private relation. Join invited delegates accept-invitation; joining waitlist follows ordinary reliability/approval rules. Existing leave handles invited/waitlisted withdrawal. Owner review may approve pending/waitlisted (capacity locked) or reject invited/pending/waitlisted. Invitations, waitlists appear in mine list (accepted_only still restricts accepted).

Private games excluded from open feed and direct UUID details for outsiders. Only owner or currently invited/pending/accepted/waitlisted participant sees private details. Withdrawing or declining revokes private-detail access immediately; own action returns sanitized resource? Leave returns `{id,visibility,status,viewer}` cannot decode ScheduledMatch, so preserve full ScheduledMatch action response once during own withdrawal while future GET is denied. No added hidden-profile disclosure to unrelated invitees: lineup masks hidden profiles until accepted lineup membership. Owner can identify voluntary waitlist applicants. `can_join` false for private outsiders or full events; `can_waitlist` true only if authorized/full/active and not currently accepted/pending/waitlisted.

Existing errors reused plus `invitation_not_pending` (409), `friendship_not_accepted` (409), `scheduled_series_conflict` (409). Series conflict may use existing version_conflict to simplify. Dynamic notifications via shared social inbox. Existing 1.1 clients ignore optional keys and do not see private games without membership.
