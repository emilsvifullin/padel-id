Padel ID 1.2.0 adds social and sports features. Five tabs provide private and group conversations, game groups, a feed with comments and reactions, player subscriptions, and an inbox. Private games support invitations, waitlists and zoned weekly schedules. Coaches expose qualifications, schedules and enrollment; training and four tournament formats include registration, partner consent, results and standings. Club pages include verified metadata, courts, maps, photos, administration and external booking links. Club news reuses existing posts with a club filter and attribution, while publication requires current administrator rights. Court availability, payments and commercial booking integrations are not fabricated. Existing account IDs, match confirmations, ordinary rating calculations and the result outbox are preserved.

Organizers can change an open event’s time and conditions without losing participants. Metadata versions reject stale edits and notify the roster. On a conflict, the edit draft preserves local changes and requires an explicit choice to keep the draft or use the latest event. The account screen opens personal event history. Conflicting score edits reload canonical values before correction. Publication forms allow correction after a definitive rejection; uncertain delivery keeps the payload and idempotency key. Sorted JSON encoding also preserves exact request bytes when rebuilding the same retry. Refresh and polling reconcile the visited canonical window of up to 150 rows, including conversations and the inbox. Private feed, comment and event collections are not persisted to disk. Moderators see only the current reported item, without surrounding private conversations or retained deleted content.

Ten additive migrations implement the new permissions, event contracts, club news and notification queue. Avatar API and private Storage enforce live sessions, visibility and owner operations; signed access paths, copying, moving and enumeration are denied. Delivery requires an agreed client update/version gate and review of previously public caches, because downloaded copies cannot be revoked by making the bucket private. Saved automatic, light and dark appearance is shared across the app. Three real UIKit Home Screen icons use lime by default; settings previews fit their labels and all three designs were verified in SpringBoard. Dynamic Type, accessible labels and Reduce Motion are respected. APNs code is implemented; the owner approved in-app notifications for 1.2.0 and deferred APNs, with shipping push disabled.
